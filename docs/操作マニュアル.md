## 2. アプリの概要

### 2.1 このツールでできること

Excelに登録したWebページを読み込み、納品前に確認したい内容をまとめて検査できます。

- 案件ごとにExcel、認証方法、検査条件を管理する
- JavaScriptで表示された後のページをPC・スマートフォンの両方で確認する
- title、description、Googleタグ、リンク、画像を自動検査する
- 検査中の進み具合と、ページごとの結果を画面で確認する
- 過去の検査を開き、再検査や2回分の比較を行う
- 任意で、リンク文言とリンク先の内容が合っているかをAIで補助判定する
- 検査結果をExcelまたは安全化JSONとして出力する

このツールは確認作業を補助するものです。画面の見た目、文章の正しさ、法令やアクセシビリティへの適合など、すべてを自動判定するものではありません。

### 2.2 検査対象と検査項目

| 項目 | 主な確認内容 |
|---|---|
| ページ取得 | ページを取得できるか、HTTP状態、最終URL、試行回数 |
| title | 描画後の`title`が1個だけあり、Excelの期待値と完全一致するか |
| description | 描画後の`meta description`が1個だけあり、Excelの期待値と完全一致するか |
| Googleタグ | Excelに登録したGTM、GA4、Google広告、Google tag、FloodlightのIDや設置方法 |
| リンク | HTTP状態、リダイレクト、ページ内・別ページアンカー、PDF、`mailto:`、`tel:`など |
| 画像 | PC・スマートフォン別の読み込み、表示、通信エラー、レスポンシブ非表示 |
| AIリンク内容照合（任意） | リンク文言・周辺文と、リンク先のtitle・h1〜h3・本文抜粋の意味が対応するか |

> [!NOTE]
> h1〜h3などの見出しは、通常の自動検査では独立した合否項目ではありません。AIリンク内容照合を使う場合に、リンク先の比較材料として取得されます。

### 2.3 検査の基本的な流れ

1. アプリを起動し、`http://127.0.0.1:3000`を開く。
2. 案件を作成し、検査条件と認証方法を設定する。
3. 決められた形式のExcelを登録する。
4. 「Excel入力プレビュー」で「入力検証OK」を確認する。
5. 「検査開始」を押す。
6. 進捗とページ別結果を確認する。
7. 必要に応じてAIリンク内容照合、再検査、履歴比較を行う。
8. ExcelレポートまたはJSON結果を出力する。

### 2.4 自動検査とAIリンク内容照合の違い

| 比較 | Webサイト自動検査 | AIリンク内容照合 |
|---|---|---|
| 目的 | 取得可否、文字列の完全一致、リンク・画像・タグの状態を機械的に確認 | リンク文言が示す内容とリンク先の意味が合うかを補助判定 |
| 実行 | 検査開始時に必ず実行 | 案件設定でOFF、MANUAL、APIから選択 |
| 主な判定 | NG、要確認、未確認、対象外、OK | match、possible_mismatch、undetermined |
| 外部AI通信 | なし | MANUALでは利用者がJSONをChatGPT/Codexへ渡す。APIではOpenAI APIへ送信 |
| 結果の扱い | 機械検査の正式な結果 | 補助情報。AIだけでNGを確定しない |

## 3. 最初に行う準備

### 3.1 必要な環境

- Windows 11
- Node.js 20以降
- npm
- 検査用Chromium（Playwrightでインストール）
- ローカルPC上で`127.0.0.1:3000`へアクセスできるブラウザ

初回セットアップでは、プロジェクトフォルダーをPowerShellで開き、次を実行します。

```powershell
npm install
npm run playwright:install
Copy-Item .env.example .env
```

`.env`の`APP_ENCRYPTION_KEY`には、32バイトの鍵をBase64または64桁の16進数で設定します。PowerShellでは次の例で生成できます。

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

生成した値を`.env`の次の行へ設定します。

```dotenv
APP_ENCRYPTION_KEY=ここに生成した値を設定
```

この鍵を失うと、保存済みのBasic認証情報を復号できません。安全な場所にも控えを保管してください。

### 3.2 開発モードで起動する

**操作する画面:** PowerShell

**操作手順:**

1. `package.json`があるプロジェクトフォルダーを開く。
2. 次を実行する。

   ```powershell
   npm run dev
   ```

3. 起動メッセージが表示されたら、ブラウザで`http://127.0.0.1:3000`を開く。

**実行結果:** 「案件一覧」画面が表示されます。

**注意事項:** 開発モードはソースコードの変更を検知して反映します。通常は変更のたびに`npm run build`を行う必要はありません。

### 3.3 本番用にビルドして起動する

**操作する画面:** PowerShell

**操作手順:**

1. ソースコードを本番用にビルドする。

   ```powershell
   npm run build
   ```

2. 本番サーバーから参照する環境変数を用意する。`node .output/server/index.mjs`は、プロジェクトの`.env`を自動では読み込みません。PowerShellやWindowsの環境変数へ`APP_ENCRYPTION_KEY`、必要に応じて`DATA_DIR`、`OPENAI_API_KEY`を設定してから起動します。Node.js 20の`--env-file`を使う場合は、次のように`.env`を読み込めます。

   ```powershell
   $env:NITRO_HOST='127.0.0.1'
   node --env-file=.env .output/server/index.mjs
   ```

3. 環境変数をすでにPowerShellまたはWindowsへ設定済みの場合は、接続先をローカルに限定してから、指定のコマンドでビルド済みサーバーを起動する。

   ```powershell
   $env:NITRO_HOST='127.0.0.1'
   node .output/server/index.mjs
   ```

   このプロジェクトでは、`NITRO_HOST`を設定してから起動する次のコマンドも利用できます。ただし、このコマンドも`.env`を自動では読み込まないため、その他の環境変数は別途設定します。

   ```powershell
   npm run start
   ```

4. ブラウザで`http://127.0.0.1:3000`を開く。

**実行結果:** ビルド済みのアプリが起動します。

**コード修正後の再ビルド:** `.vue`、`.ts`、CSS、設定ファイルなどアプリのソースを変更した場合、本番モードへ反映するには、サーバーを終了して`npm run build`を再実行し、再起動します。案件データ、Excel、検査履歴の変更だけなら再ビルドは不要です。

### 3.4 `127.0.0.1`でアクセスする理由

`127.0.0.1`は、現在使っているPC自身だけを示すアドレスです。本アプリのAPIはHost、Origin、クロスサイト要求、CSRFトークンを確認し、`127.0.0.1`以外からの操作を拒否します。

`http://localhost:3000`、PC名、LAN内IPアドレスではなく、必ず次を使用してください。

```text
http://127.0.0.1:3000
```

### 3.5 アプリを終了する

**操作する画面:** アプリを起動したPowerShell

**操作手順:** `Ctrl`キーを押しながら`C`キーを押します。

**実行結果:** サーバーが停止し、ブラウザからアプリへ接続できなくなります。

**注意事項:** 検査中に終了すると、次回起動時にその検査は「中断」として確定します。完了済みページは保持されますが、自動的な続行や再実行は行われません。

### 3.6 データの保存場所

初期設定では、プロジェクトフォルダー内の`data`フォルダーに保存します。`.env`の`DATA_DIR`で別の場所を指定できます。相対パスは、アプリを起動したフォルダーを基準に解決されるため、本番運用では絶対パスを推奨します。

```dotenv
DATA_DIR=C:\WebCheckData
```

主な保存内容は[7. データ管理と注意事項](#7-データ管理と注意事項)を参照してください。

## 4. 基本操作（案件作成から検査完了まで）

### 4.1 案件を作成する

**操作する画面:** 「案件一覧」→「案件を作成」

**操作手順:**

1. 右上の「新しい案件」を押す。
2. 「案件名」を入力する。
3. ページ並列数、タイムアウト、必要であれば許可ホスト、AI、認証を設定する。
4. 「案件を作成」を押す。

**入力例:**

| 項目 | 入力例 |
|---|---|
| 案件名 | コーポレートサイト 2026年10月納品 |
| ページ並列数 | 2 |
| タイムアウト | 30000 |
| AIリンク内容判定 | OFF |
| 認証方式 | なし |

**実行結果:** 作成した案件の詳細画面へ移動します。

### 4.2 Excelを登録する

**操作する画面:** 案件詳細の「入力ファイル」

**操作手順:**

1. 「ファイルを選択」で`.xlsx`ファイルを選ぶ。
2. 「Excelを登録」を押す。
3. 「Excelを案件フォルダへコピー保存しました。原本は変更していません。」と表示されることを確認する。
4. 下に表示される「Excel入力プレビュー」を確認する。

**実行結果:** 選んだファイルは`input/current.xlsx`へコピーされ、元のファイルは変更されません。「入力検証OK」なら検査を開始できます。「修正が必要」なら、表示された開始不可の内容を元Excelで修正して再登録します。

### 4.3 検査を開始する

**操作する画面:** 案件詳細の「Webサイト自動検査」

**操作手順:**

1. Excel入力プレビューが「入力検証OK」であることを確認する。
2. 認証が必要な案件では「認証情報: 設定済み」であることを確認する。
3. 「検査開始」を押す。

**実行結果:** 新しいrunが作成され、「開始待ち」から順に状態が変わります。ページが完了するたびに途中結果が保存され、画面は2秒ごとに更新されます。

### 4.4 検査完了を確認する

**操作する画面:** 「Webサイト自動検査」の選択中の履歴

**操作手順:**

1. 状態が「完了」になるまで待つ。
2. 「完了ページ数 / 総ページ数」と進捗が100%であることを確認する。
3. NG、要確認、未確認、対象外、OKの件数を確認する。
4. 「ページ別結果」を開き、NG、要確認、未確認を優先して確認する。
5. 必要ならExcelレポートを出力する。

**注意事項:** 状態が「失敗」「キャンセル済み」「中断」の場合でも、完了済みページの途中結果は残ります。総ページ数すべてが完了しているとは限りません。

## 5. 各機能の詳しい使い方

### 5.1 案件管理

#### 5.1.1 案件一覧

案件カードには、案件名、登録済みExcel名、認証情報の有無、最新検査の状態・ページ数・判定集計、直近の完了結果が表示されます。「編集」を押すと案件詳細を開きます。

読み取れない履歴がある場合は、破損件数と過大件数が警告表示されます。正常な履歴だけが表示され、ファイルの自動削除や修復は行われません。

#### 5.1.2 基本設定の各項目

| 項目 | 説明 | 入力範囲・注意 |
|---|---|---|
| 案件名 | 一覧やレポートで案件を識別する名前 | 必須、200文字以内 |
| ページ並列数 | 同時に検査するページ数 | 1〜3。増やすと速くなる場合がありますが、対象サイトへの負荷も増えます |
| タイムアウト（ミリ秒） | ページ移動や認証画面を待つ時間 | 1,000〜120,000、1,000刻み。30,000は30秒。リンク検査15秒・画像検査1端末60秒の固定上限はこの欄では変わらない |
| ローカル・私設IPへの明示許可ホスト | 通常は安全のため拒否される社内・ローカル環境のホスト名 | 1行1件、最大50件。検査に必要なホストだけを指定する |
| AIリンク内容判定 | OFF、MANUAL、API | 詳細は[5.4](#54-aiリンク内容照合)を参照 |
| 認証方式 | なし、Basic認証、パスワード保護 | 対象サイトに合わせる |

設定を変更したら「変更を保存」を押します。保存後の設定は次の新規検査で使われます。過去の検査結果の設定は変わりません。

#### 5.1.3 ローカル・私設IPへの明示許可ホスト

通常、`127.0.0.1`、`10.x.x.x`、`192.168.x.x`などのローカル・私設アドレスへの検査通信は拒否されます。社内ステージングなどを検査する場合だけ、URLのホスト名を1行ずつ入力します。

```text
staging.example.local
192.168.10.25
```

URL全体やパスは入力せず、ホスト名またはIPアドレスだけを入力します。DNSの応答に公開アドレスと非公開アドレスが混在する場合は、許可していても拒否されます。

#### 5.1.4 認証設定

**認証なし**

公開サイトなど、ログイン不要の場合に選びます。

**HTTP Basic（画面表示は「Basic認証」）**

1. 認証方式で「Basic認証」を選ぶ。
2. ユーザー名とパスワードを入力する。
3. 「案件を作成」または「変更を保存」を押す。

認証情報は`APP_ENCRYPTION_KEY`を使いAES-256-GCMで暗号化し、案件データとは別の`secrets.enc.json`へ保存されます。編集画面に既存値は表示されません。「認証情報は設定済みです」と表示されているときは、変更する場合だけ再入力します。

**Password Protected（画面表示は「パスワード保護」）**

WordPressの「Password Protected」プラグインが出力する、サイト全体の保護フォームを対象とします。

1. 認証方式で「パスワード保護」を選ぶ。
2. パスワードを入力する。
3. 保存する。

このパスワードは案件別の`password-protected.secret.json`へ平文で保存されます。Windowsのフォルダー権限で`DATA_DIR`を現在の利用者だけが読めるようにしてください。別の認証方式へ変更すると、この専用ファイルは削除されます。

**旧フォーム認証**

旧バージョンの案件を開いたときだけ警告される読み取り互換機能です。新規設定はできません。「なし」「Basic認証」「パスワード保護」のいずれかへ設定し直してください。旧認証情報は自動削除・変換されません。

#### 5.1.5 案件を編集する

**操作する画面:** 「案件一覧」→対象案件の「編集」

1. 必要な項目を変更する。
2. 「変更を保存」を押す。
3. 「案件設定を保存しました。」を確認する。

アーカイブ中の案件は設定とExcelを変更できません。先にアーカイブを解除してください。

#### 5.1.6 アーカイブする・解除する

案件一覧の「アーカイブ」、または案件詳細右上の「アーカイブ」を押します。一覧画面では確認ダイアログが表示されます。

アーカイブすると通常の案件一覧から外れ、新しい検査、設定変更、Excel変更ができなくなります。案件ファイルや履歴は移動・削除されません。上部メニューの「アーカイブ」から対象案件を開き、「解除」を押すと通常一覧へ戻せます。

案件を完全に削除する画面機能は実装されていません。

### 5.2 Excel入力

#### 5.2.1 必要なファイル形式

- 拡張子は`.xlsx`のみ
- ファイルサイズは20MiB以下
- シート名と1行目の見出しは完全一致が必要
- 数式の計算結果は使わない
- ページ入力範囲に影響する結合セルは使用しない

#### 5.2.2 「納品前のチェック」シート

| 列 | 1行目の見出し | 必須 | 入力内容 |
|---|---|---|---|
| A | ページ名 | 任意 | 結果画面で分かりやすくする名前。空欄時はURLを表示名に使う |
| B | URL | 有効な行では必須 | `http://`または`https://`から始まる完全なURL |
| C | title | 任意だが入力推奨 | 期待するtitle。実際の値と完全一致で判定 |
| D | description | 任意だが入力推奨 | 期待するmeta description。実際の値と完全一致で判定 |

**入力例:**

| ページ名 | URL | title | description |
|---|---|---|---|
| トップページ | `https://example.com/` | 会社名｜公式サイト | 会社のサービスとお知らせをご案内します。 |
| 会社概要 | `https://example.com/company/` | 会社概要｜会社名 | 会社情報、所在地、沿革をご案内します。 |
| お問い合わせ | `https://example.com/contact/` | お問い合わせ｜会社名 | お問い合わせフォームはこちらです。 |

URLはフラグメント（`#section`）を除いて同じページとしてまとめられます。ホスト名の大文字小文字などもURLの標準形式へそろえられます。同じURLが複数行にある場合、元行と期待値の一致・空欄・矛盾がプレビューに表示されます。

titleまたはdescriptionを空欄にすると、「無いことを期待する」のではなく「期待値が空欄のため要確認」になります。空であることを自動的にOKにしたい使い方には対応していません。

#### 5.2.3 「Googleタグ」シート

| 列 | 1行目の見出し | 必須 | 入力内容 |
|---|---|---|---|
| A | タグ名 | 任意 | タグを識別する名前。`head用`、`body用`の文字があるとGTMの設置位置判定に使う |
| B | 設置コード | 有効な行では必須 | GoogleタグのIDまたは設置コード |

対応するID形式は次のとおりです。

- `GTM-...`：Google Tag Manager
- `G-...`：GA4
- `AW-...`：Google広告
- `GT-...`：Google tag
- `DC-...`：Floodlight

**入力例:**

| タグ名 | 設置コード |
|---|---|
| GTM head用 | `<script>...GTM-EXAMPLE...</script>` |
| GTM body用 | `<noscript>...GTM-EXAMPLE...</noscript>` |
| GA4 | `G-EXAMPLE123` |

実在する案件のIDやコードをマニュアルへ転記しないでください。上記は形式を示す架空例です。

#### 5.2.4 非表示行、空白行、フィルター

- 完全な空白行は「空白行」として数え、検査しません。
- Excelで非表示状態が保存されている行は「非表示除外」として検査しません。
- オートフィルターの条件式自体は評価しません。フィルター範囲だけがあり、行の非表示状態が保存されていない場合は除外できません。
- B列が空欄、またはHTTP/HTTPS以外のURLの行は警告として除外します。
- 有効URLが1件もない場合は開始不可です。

#### 5.2.5 Excel入力プレビューの見方

| 表示 | 意味 |
|---|---|
| 対象行 | 1行目を除き、最後に内容がある行までの行数 |
| 有効行 | 検査入力として使える行数 |
| 固有URL | 重複をまとめた実際の検査ページ数 |
| 空白行 | 4列すべて空の行数 |
| 非表示除外 | Excelで非表示として保存された行数 |
| URL欠落・不正 | B列が空欄、または有効なHTTP/HTTPS URLでない行数 |
| 重複URL | 同じページとしてまとめられるURLのグループ数 |
| 結合セル | 検出した結合範囲数 |
| 数式セル | 値として採用しない数式セル数 |
| 有効タグ行 | IDを抽出できたGoogleタグ行数 |
| 警告・エラー | すべての警告と開始不可の合計 |

「警告」は検査を開始できる場合があります。「開始不可」が1件でもあると「修正が必要」になります。

#### 5.2.6 よくあるExcel入力エラー

| 表示・原因 | 対処 |
|---|---|
| 必須シートがない | シート名を「納品前のチェック」「Googleタグ」に完全一致させる |
| 見出しが違う | 1行目を指定の文字へ直す。全角・半角や余分な空白にも注意する |
| 有効なURLが1件もない | B列へ完全なHTTP/HTTPS URLを1件以上入力する |
| URL欠落・不正 | `https://example.com/`のように入力する。`www.example.com`だけ、`ftp://...`は不可 |
| 数式セル | 数式ではなく、表示したい文字を値として貼り付ける |
| 結合セル | A〜D列のデータ範囲にかかる結合を解除する |
| タグコードが空、IDを抽出できない | B列へ対応形式のIDまたは設置コードを値で入力する |
| ファイルが大きすぎる・危険な圧縮構造 | 不要なシート、画像、書式を削除して別名保存する。改善しなければ開発者へ連絡する |

### 5.3 Webサイト自動検査

#### 5.3.1 検査開始と検査中の表示

「検査開始」を押すと、その時点のExcelを読み直し、設定の控えをrunへ保存します。アプリ全体で同時に実行できる検査は1件です。

状態は通常、次の順に進みます。

| 状態 | 意味 |
|---|---|
| 開始待ち (`queued`) | 実行開始を待っている |
| Excel読込中 (`reading_input`) | 登録済みExcelを再確認している |
| 認証中 (`authenticating`) | 保護サイトへログインしている |
| 検査中 (`checking`) | ページ、リンク、画像、タグを検査している |
| AI判定中 (`ai_checking`) | APIモードでAI判定している |
| 完了 (`completed`) | 一連の処理が終了した |
| 失敗 (`failed`) | 検査全体を続けられないエラーで終了した |
| キャンセル済み (`canceled`) | 利用者がキャンセルした。完了済み結果は保持 |
| 中断 (`interrupted`) | アプリ終了などを次回起動時に検出した。自動再実行なし |

検査中は「2秒ごとに更新中」、完了ページ数、総ページ数、パーセント、判定集計が表示されます。画面を再読み込みしても保存済みの途中結果を再表示できます。

#### 5.3.2 PC・スマートフォン検査

- PC表示：1366 × 768
- スマートフォン表示：375 × 667、Pixel 5相当の端末設定

画像は両方の表示でスクロールしながら確認します。レスポンシブCSSにより明確に非表示で、操作状態に依存しない画像は「対象外」になります。非表示かどうかを安全に確定できない場合は「要確認」です。

#### 5.3.3 判定の意味

| 判定 | 意味 | 利用者の対応 |
|---|---|---|
| NG | 明確な不一致、欠落、リンク切れ、取得失敗などを検出 | 原則として内容を確認し、修正または理由を記録する |
| 要確認 | 例外的HTTP状態、期待値空欄、判定材料不足など、人の確認が必要 | 根拠、実ページ、仕様を照合する |
| 未確認 | ページ取得不能などで、その項目を検査できなかった | 原因を解消して再検査する |
| 対象外 | レスポンシブ非表示など、条件上検査対象から外した | 除外理由が妥当か確認する |
| OK | 実装された基準を満たした | 必要に応じて目視確認も行う |

画面上の集計はページごとの6つの項目（ページ取得、title、description、Googleタグ、リンク、画像）を数えます。リンクや画像の個別件数とは一致しない場合があります。

#### 5.3.4 title・descriptionの検査

JavaScript描画後のDOMを確認します。

- 0個ならNG（「ありません」）
- 複数ならNG（「複数あります」）
- Excelに数式がある場合は要確認
- 重複URLの期待値が矛盾する場合は要確認
- Excel期待値に空欄行を含む場合は要確認
- 1個だけあり、Excelの期待値と文字列が完全一致すればOK
- 空白、記号、全角・半角などを含め、完全一致しなければNG

不一致時は期待値と実際の値、および文字差分が表示されます。画面では空白を`·`、タブを`⇥`、改行を`↵`などで見えるように表示します。

#### 5.3.5 Googleタグの検査

元HTML、描画後DOM、Google関連通信を使い、直接設置、GTM経由、Google tag経由などを確認します。期待したIDがない場合、不適切な重複直接設置などはNGです。通信でしか確認できず設置方法を特定できない場合や、GTM bodyコードの位置を確定できない場合は要確認です。

「Googleタグ検出詳細」を開くと、ID、検出方法、設置方法、位置、出現回数、判定理由、根拠を確認できます。

#### 5.3.6 リンクの検査

- HTTP/HTTPSリンクは状態コードとリダイレクト先を確認します。
- HTTP 200番台は原則OKです。
- 401、403、405、429は、一律にリンク切れとせず要確認です。
- その他の300番台、400番台、500番台は原則NGです。
- ページ内・別ページアンカーは、指定IDまたはnameがあるか確認します。
- `.pdf`のURLでContent-TypeがPDFでない場合は要確認です。
- 空の`href`は要確認です。
- `mailto:`と`tel:`は形式だけを確認し、実際の送信・発信は行いません。
- `javascript:`、`data:`、その他HTTP/HTTPS以外は通信せず、要確認として記録します。

「リンク検査詳細」では元のhref、メッセージ、HTTP状態、リダイレクト回数、最終到達先、根拠を確認できます。

#### 5.3.7 画像の検査

`img`、`picture`、`srcset`、CSS背景、`::before`、`::after`の画像候補をPC・スマートフォン別に確認します。

- 通信エラー、デコード失敗、表示失敗はNG
- 読み込み状態を時間内に特定できない場合は要確認
- 明確なレスポンシブ非表示は対象外
- 読み込みと表示を確認できればOK

「画像検査詳細」では端末、画像種別、URL、出現箇所、メッセージ、非表示の根拠を確認できます。

#### 5.3.8 ページ取得失敗時の扱い

ページ取得自体はNGになります。title、description、Googleタグ、リンク、画像は「ページ取得不能のため未確認」として追加されます。1ページの失敗だけで、他ページを成功扱いにしたり、すべての検査を直ちに中止したりはしません。ただし認証失敗など全体に関係する問題は、run全体が失敗することがあります。

検査を手動でキャンセルした場合、未完了ページをNGとして追加しません。

### 5.4 AIリンク内容照合

#### 5.4.1 AIリンク内容照合とは

通常のリンク検査は「リンク先へ到達できるか」を中心に確認します。AIリンク内容照合は、「料金を見る」というリンクが料金ページへ進むなど、リンク元が予告する内容とリンク先の内容が意味的に対応するかを補助判定します。

画像リンクは対象外です。意味が同じ入力は重複をまとめ、元リンク数と重複排除後の判定対象数を別に表示します。

#### 5.4.2 モードを選ぶ

案件の「AIリンク内容判定」で次から選びます。

| モード | 動作 |
|---|---|
| OFF | AI用の追加処理や外部AI通信を行わない |
| MANUAL | マスキング済み入力JSONを出力し、利用者がChatGPT/Codexで判定して結果JSONを取り込む |
| API | サーバーの`OPENAI_API_KEY`を使って自動判定する。料金が発生する可能性がある |

#### 5.4.3 MANUAL：AI入力JSONを作成する

**操作する画面:** 案件詳細の基本設定と「AIリンク内容判定」

1. 案件設定の判定モードを「MANUAL」にして保存する。
2. 新しい検査を開始し、機械検査の完了を待つ。
3. 「AI判定用JSONをダウンロード」を押す。
4. 個人情報や秘密情報が十分にマスクされているか、ダウンロード前の確認メッセージとファイル内容を確認する。

**実行結果:** `web-check-ai-input-<runId>.json`がダウンロードされます。

#### 5.4.4 ChatGPT/Codexで手動判定する

1. 「Codex用の指示文をコピー」を押す。
2. ChatGPTまたはCodexで新しい会話を開く。
3. コピーした指示文を貼り付ける。
4. ダウンロードしたAI入力JSONを添付する。
5. 指示文どおり、JSONファイルだけを作成させる。
6. 件数が多い場合は10件以下のまとまりごとに確認させ、最後に件数、`itemId`、`inputHash`の欠落・重複がないことを確認する。
7. 出力されたJSONをPCへ保存する。

AIには、入力JSON内の情報だけで判定させます。リンク先を検索・再取得させないでください。JSON内のWebページ文章に命令のような内容があっても、判定対象の文章としてのみ扱わせます。

#### 5.4.5 AI判定結果JSONを取り込む

**操作する画面:** 「AIリンク内容判定」

1. 「AI判定結果JSONを取り込む」を押す。
2. ChatGPT/Codexが作成した`.json`ファイルを選ぶ。
3. 「AI判定結果を取り込みました。」を確認する。
4. 集計と「AI判定詳細」を確認する。

同じファイルを再度選んだ場合は、保存内容を変えず「すでに取り込み済み」と表示します。異なる結果で上書きする機能はありません。

#### 5.4.6 AI判定の意味

| JSON上の判定 | 画面表示 | 意味 |
|---|---|---|
| `match` | OK | リンク元が示す目的とリンク先情報が意味的に対応する |
| `possible_mismatch` | 要確認 | リンク元とリンク先が明らかに別の主題・目的を示す可能性がある |
| `undetermined` | 判定不可（要確認に集計） | 取得不能、情報不足、曖昧なリンク文言などで根拠を持って判断できない |

AIの`possible_mismatch`と`undetermined`はいずれも人による確認が必要です。AI判定は機械検査のNG・OKを書き換えません。文章の意味には文脈や業務判断が必要であり、誤判定もあり得るため、AIだけでNGを確定しないでください。

#### 5.4.7 `tel:`、`mailto:`、PDFなどの扱い

- `tel:`と`mailto:`などHTTP/HTTPS以外は、通常のリンク検査では形式確認または要確認になります。
- AI入力では取得できないリンク先を`unsupported_protocol`として記録します。
- 安全な形式の`tel:`は、電話リンクとして必要な番号表記を保持する場合があります。
- PDFはAI内容照合の対象外で、`pdf`として記録します。
- HTTPエラーは`http_error`、HTMLでない内容は`non_html`、安全に取得できなかった場合は`fetch_failed`です。
- これらはAIが推測で一致とせず、原則として`undetermined`を検討するための情報です。

#### 5.4.8 マスキング表示

AI入力では、次のような表示に置き換わることがあります。

| 表示 | 意味 |
|---|---|
| `[MASKED_EMAIL]` | メールアドレスと判定された文字列 |
| `[MASKED_PHONE]` | 電話番号と判定された文字列 |
| `[MASKED_HIGH_ENTROPY]` | 長くランダム性が高い秘密値らしい文字列 |
| `[MASKED_JWT]` | JWT形式らしい文字列 |
| `[MASKED_API_KEY]` | APIキー形式らしい文字列 |
| `[MASKED_SECRET]` | token、password、sessionなど名前付き秘密値 |
| `[MASKED]` | URL内のユーザー名、パスワード、秘密性の高いクエリ値 |

これはエラーではなく、外部AIへ渡す情報を減らすSecurity-Cの保護処理です。ただし自動検出は完全ではありません。送信前に、実際の案件名、認証情報、電話番号、メールアドレス、顧客情報などが残っていないか人が確認してください。

#### 5.4.9 API方式

API方式を使う場合は、`.env`へ`OPENAI_API_KEY`を設定してアプリを再起動します。画面でモデル、価格プロファイル、1検査の料金上限（USD）を設定できます。APIキー自体は画面、案件JSON、結果JSONへ保存されません。

検査中は入力・キャッシュ入力・出力トークン数、概算料金、料金上限、API失敗件数、上限到達の有無が表示されます。料金は保存した価格プロファイルによる概算で、実際の請求額を保証しません。認証エラー、利用枠不足、レート制限、サーバーエラー、料金上限到達などでAPI判定が失敗する場合があります。機械検査結果は保持されます。

> [!WARNING]
> OpenAI APIへ受理済みの処理は、検査をキャンセルしても料金が発生する場合があります。

### 5.5 検査結果・履歴

#### 5.5.1 結果画面の見方

左側の「検査履歴」でrunを選ぶと、右側へその結果が表示されます。

- 状態、実行日時、runId、再実行元runId
- 開始・終了日時
- 進捗
- ページ集約項目の判定件数
- Excel入力の対象行、有効行、除外行、固有ページ数
- AI判定の状態と集計
- ページ別の期待値、実測値、差分、根拠
- Googleタグ、リンク、画像の個別詳細

ページ別結果はNG、要確認、未確認、対象外、OKの順で項目を表示します。OK以外を含むページは初期状態で開きます。

#### 5.5.2 検査履歴

履歴には実行日時、状態、完了ページ数、総ページ数、NG・要確認・対象外件数が表示されます。画面を閉じても履歴は`DATA_DIR`へ残ります。

`completed`は「一連の処理が最後まで終了した」状態です。すべての個別項目がOKという意味ではありません。完了したrunにもNGや要確認が含まれます。

#### 5.5.3 全URLを再実行する

**操作する画面:** 終了済みrunの結果右上

1. 再実行元にしたい履歴を選ぶ。
2. 「全URLを再実行」を押す。
3. 検査条件を「現在の案件設定」または「過去runの設定スナップショット」から選ぶ。
4. 過去runと現在設定の差分を確認する。
5. AIモードを選ぶ。初期値は必ずOFF。
6. APIを選ぶ場合は料金発生の確認にチェックする。
7. 「新しいrunで再実行」を押す。

現在登録されているExcelを読み直し、新しいrunIdで全URLを検査します。元runとExcelは変更しません。過去runの設定を選んでも、認証情報と認証手順は現在の案件設定を使います。過去と現在の認証モードが違う場合は開始できません。

#### 5.5.4 履歴を比較する

**操作する画面:** 案件詳細下部の「履歴を比較」

1. 「比較元run」に変更前・基準にしたいrunを選ぶ。
2. 「比較先run」に変更後・確認したいrunを選ぶ。
3. 「比較する」を押す。

再実行したrunを選んでいる場合は「再実行元と比較」で組み合わせを自動設定できます。通常は完了runが2件以上あると、新しいものを比較先、その1つ前を比較元として初期選択します。完了runが2件未満でも手動選択は可能です。同じrun同士は比較できません。

**比較元と比較先:** 「比較元」は変更前、「比較先」は変更後として扱います。そのため「NG解消」は比較元でNG、比較先でNGでなくなったもの、「NG発生」は比較先で新しくNGになったものです。

確認できる内容は次のとおりです。

- ページ集約、個別詳細、AI判定、Excel入力ごとの件数
- NG解消、NG発生、NG継続、判定変化
- 対象追加、対象削除、片側で未観測、対応不確実
- 判定遷移の集計
- ページ並列数、タイムアウト、認証、AIモードなど検査条件の差
- 期待値、実測値、メッセージの変更前・変更後

カテゴリ、ページのURL・名前、項目名で絞り込めます。比較対象が失敗・中断などで部分的な結果の場合は、警告と「対応不確実」が出ることがあります。

### 5.6 レポート出力

#### 5.6.1 Excelレポート

**操作する画面:** 終了済みrunの結果右上

1. 出力したい履歴を選ぶ。
2. 「Excelレポートをダウンロード」を押す。
3. ブラウザのダウンロード完了を確認する。
4. `web-check-report-<runId>.xlsx`をExcelで開く。

検査実行中はExcelレポートを出力できません。レポートは保存済み結果から`runs/<runId>/report.xlsx`へ再生成され、同じファイルがダウンロードされます。

| シート | 内容 |
|---|---|
| 検査サマリー | 案件・run・入力・判定件数・AI状態・使用量などの概要 |
| NG・要確認一覧 | NG、要確認、未確認だけを確認・修正管理しやすい列順で表示 |
| 全検査結果 | ページ項目、タグ、リンク、画像、AIを含む全個別結果 |

詳細には、URL、ページ名、元行、項目、判定、問題、期待値、実測値、端末、参照元、日時、差分、根拠などが含まれます。「修正状況」は「未対応」「対応中」「修正済み」から選べ、「備考」も入力できますが、これらは出力したExcelだけの情報です。レポートを再生成すると「未対応」または空欄へ戻り、`result.json`には反映されません。

#### 5.6.2 JSON結果

「JSON結果をダウンロード」を押すと、`web-check-result-<runId>.json`を出力します。実行中は「現在までのJSONをダウンロード」と表示され、その時点までに保存された途中結果のスナップショットになります。

JSONには、run情報、設定の控え、Excel入力の控え、ページ・リンク・画像・Googleタグ・AI結果、使用量、終了理由などが含まれます。出力時にURL認証情報や秘密性の高い値をマスクしますが、一般的なメールアドレス・電話番号、対象サイトの文章は残る場合があります。

**出力後の確認:**

1. runIdと案件が正しいか確認する。
2. 完了状態と完了ページ数を確認する。
3. URL、文章、個人情報、認証情報が含まれていないか確認する。
4. 外部共有は必要な相手・方法に限定する。

## 6. エラーと対処方法

### 6.1 まず確認すること

1. アプリを起動したPowerShellにエラーが出ていないか。
2. URLが`http://127.0.0.1:3000`か。
3. 対象案件がアーカイブ中でないか。
4. Excel入力プレビューに「開始不可」がないか。
5. 認証情報が設定済みか。
6. 対象サイトを通常のブラウザで開けるか。
7. 一時的な問題なら、時間を置いて新しいrunで再検査できるか。

次の表で「利用者で対応」に記載した確認を行っても解消しない場合は、「開発者調査」の情報を添えて担当者へ連絡してください。認証情報や秘密値は、ログや画面コピーへ貼り付けないでください。

### 6.2 エラー別の原因と対処

| 表示・状態 | 主な原因 | 利用者で対応できること | 開発者による調査が必要な場合 |
|---|---|---|---|
| `Failed to fetch` | アプリ停止、接続先の間違い、ブラウザとAPIの接続切れ、セキュリティ拒否 | PowerShellで起動中か確認し、`http://127.0.0.1:3000`を開き直す。ページを再読み込みする | 正しいURL・起動状態でも繰り返す場合。発生時刻、操作、ブラウザの開発者ツールに出る状態コードを伝える |
| 「このAPIは127.0.0.1からのみ利用できます」 | `localhost`、PC名、LAN内IP、プロキシなど別Hostで開いた | アドレス欄へ`http://127.0.0.1:3000`を直接入力する | 正しいURLでも出る場合。リバースプロキシやセキュリティソフトの影響を調査 |
| Basic認証エラー、401・403 | ユーザー名・パスワード違い、対象サイト側の制限 | 案件設定で認証方式を確認し、認証情報を再入力して保存。通常ブラウザでも確認 | 正しい認証情報でも失敗する、認証方式が特殊、IP制限や多要素認証がある場合 |
| 「パスワード保護の認証に失敗しました」 | パスワード違い、WordPress Password Protected以外のフォーム、フォーム構造の変更 | パスワードを再入力し、対象URLを通常ブラウザで確認 | 正しいパスワードでフォームが出続ける、送信先安全確認で拒否される場合 |
| ページ取得失敗／`PAGE_FETCH_FAILED` | DNS、TLS、接続拒否、対象サイト停止、想定外応答 | 対象URLをブラウザで開く。URLと許可ホストを確認し、再検査 | ブラウザでは開けるのに継続して失敗。runId、URLのマスク済み表記、エラーコードを伝える |
| 一時的な通信エラー／`TRANSIENT_NETWORK_ERROR` | タイムアウト、接続リセット、接続拒否など | 時間を置いて再検査。必要ならタイムアウトを増やす | 同じページで再現し続ける、対象サイトの応答は正常な場合 |
| タイムアウト | ページやリンクが遅い、画像が多い、対象サイトが応答しない | ページ取得・認証ならタイムアウトを30,000から60,000などへ増やし、ページ並列数を下げる。リンクは固定15秒、画像は1端末60秒なので、該当詳細も確認する | ページ設定を上限120,000にしても失敗する、固定上限のリンク・画像で毎回再現する場合 |
| 「画像の通信エラーを確認しました」 | 画像URLの404・接続失敗・配信制限など | 画像URLと対象ページをブラウザで確認。CDN、公開範囲、URLを修正して再検査 | ブラウザで表示されるのにNG、認証付きCDNや特殊な遅延読み込みの場合 |
| 画像が「要確認」 | 端末別の60秒上限、読み込み状態を特定できない、操作後に表示される画像 | ページをPC・スマートフォン幅で目視確認。再検査 | 毎回同じ画像が要確認で自動判定改善が必要な場合 |
| `unsupported_protocol` | `tel:`、`mailto:`などHTTP/HTTPS以外で、AIがリンク先本文を取得できない | エラーではない。通常リンク検査の形式判定を確認し、AI結果は`undetermined`を中心に人が判断 | HTTP/HTTPSリンクなのに表示される場合 |
| `[MASKED_HIGH_ENTROPY]` | 長くランダム性が高い秘密値らしい文字列を自動保護 | エラーではない。元の値を外部へ出さず、文脈が失われていれば人が確認 | 通常文章が大量に誤マスクされ、判定できない場合 |
| `[MASKED_PHONE]` | 電話番号らしい文字列をAI入力で保護 | エラーではない。必要に応じて元ページを手元で確認 | 電話リンクとして必要な番号まで不適切に消え、判定へ継続的に影響する場合 |
| Excelを解析できない／読み込みエラー | `.xlsx`以外、破損、20MiB超過、危険なZIP構造、読み取り失敗 | Excelで開けるか確認し、`.xlsx`で別名保存。不要な内容を削除。正しいファイルを再登録 | 正常な小容量`.xlsx`でも解析できない場合。機密情報を除いた再現用ファイルを用意 |
| 「Excel入力に致命的な問題」 | 必須シート・見出し欠落、結合セル、有効URLゼロ | 入力プレビューの「開始不可」をすべて修正し、再登録 | 表示内容とExcelが一致しない場合 |
| AI判定JSONが不正 | JSON文法、5MiB超過、形式違い、別run、項目不足・重複・ハッシュ不一致 | 元のAI入力とコピーした指示文を使い、JSONだけを再生成。ファイルを手編集しない | 正しい手順で再生成しても取り込めない。エラー文とrunIdを伝える |
| 「異なるAI判定結果は…上書きできません」 | 同じrunへ別の結果を取り込もうとした | 既存結果を使用する。別判定が必要なら新しいrunで再検査する | 取り込み済みの状態が不明、保存データの修復が必要な場合 |
| OpenAI API認証・利用枠エラー | APIキー不正、残高・利用枠不足 | `.env`の`OPENAI_API_KEY`を確認し再起動。OpenAI側の利用状況を確認 | 正しい設定でも継続する、API応答形式エラーが出る場合 |
| ローカル・私設アドレスへのアクセス拒否 | SSRF対策により私設IPを既定拒否 | 対象が信頼できる社内環境なら、案件設定へホストを明示追加 | 公開サイトが私設IP判定される、DNS応答混在が発生する場合 |
| 読み取れない履歴（破損・過大） | `result.json`破損または50MiB超過 | 他の正常な履歴を使用。該当データを直接編集・削除しない | バックアップからの復元、原因調査、データ修復が必要 |

### 6.3 AI判定JSON取り込みエラーの確認順

1. 選んだファイルが`.json`で5MiB以下か確認する。
2. コードブロックの記号や説明文を含めず、JSONだけで保存されているか確認する。
3. `projectId`、`runId`、`inputBundleId`がダウンロード元と同じか確認する。
4. 全`items`の`itemId`と`inputHash`が変更されず、各1回だけ出力されているか確認する。
5. `verdict`が`match`、`possible_mismatch`、`undetermined`のいずれかか確認する。
6. `reason`が空でなく500文字以内か確認する。
7. 直らない場合は、AI入力JSONと結果JSONを外部共有せず、まずエラー文とrunIdだけを開発者へ伝える。

## 7. データ管理と注意事項

### 7.1 保存されるデータ

初期の`DATA_DIR=./data`では、おおむね次の構成になります。

```text
data/
├─ .ai-signing-key
├─ .url-identity-key
├─ .url-identity-key.initialized
└─ projects/
   └─ <案件UUID>/
      ├─ project.json
      ├─ secrets.enc.json                 # Basic認証など。存在する場合
      ├─ password-protected.secret.json   # Password Protected。存在する場合
      ├─ input/
      │  └─ current.xlsx
      └─ runs/
         └─ <runId>/
            ├─ input-snapshot.json
            ├─ result.json
            ├─ events.jsonl
            └─ report.xlsx                # レポート生成後
```

- `project.json`：案件名と設定
- `input/current.xlsx`：登録したExcelのコピー
- `input-snapshot.json`：run開始時の安全化された入力控え
- `result.json`：途中・最終結果。ページ完了ごとに更新
- `events.jsonl`：状態変更などのイベント記録
- `report.xlsx`：そのrunから最後に生成したExcelレポート

案件をアーカイブしても、これらは削除・移動されません。

### 7.2 認証情報の保存

| 種類 | 保存方法 | 注意 |
|---|---|---|
| Basic認証 | `APP_ENCRYPTION_KEY`を使うAES-256-GCM暗号化 | `.env`の鍵を失うと復号不能。別案件へファイルだけ移しても復号できない |
| Password Protected | `password-protected.secret.json`へ平文 | `DATA_DIR`を現在のWindows利用者だけが読める場所に置く |
| OpenAI APIキー | 環境変数`OPENAI_API_KEY` | 案件・結果・画面へ保存しない |

認証情報を画面やレポートへ意図的に出力しない実装ですが、対象サイト由来の文章に秘密情報が含まれている場合まで完全に防げるとは限りません。

認証方式を「なし」や別方式へ変更しても、既存の`secrets.enc.json`に保存された旧Basic認証情報などは自動削除・変換されません。Password Protected専用の`password-protected.secret.json`だけは、別方式へ変更したときに削除されます。不要な旧認証データの完全削除が必要な場合は、バックアップ後に開発者へ依頼してください。

### 7.3 バックアップ

**アプリを終了してから**、次をまとめてバックアップします。

1. `DATA_DIR`全体
2. `.env`、または少なくとも同じ`APP_ENCRYPTION_KEY`を復元できる安全な記録

特定案件フォルダーだけでなく、`DATA_DIR`直下の`.ai-signing-key`、`.url-identity-key`、`.url-identity-key.initialized`も必要です。URL識別鍵の初期化済みマーカーがあるのに鍵がない場合、アプリは鍵を勝手に再生成せず安全に停止します。

バックアップ先も認証情報を含む機密データとして扱い、暗号化された媒体やアクセス制限された場所を使用してください。

### 7.4 データを削除・移動するとき

- アプリを終了してから作業する。
- `DATA_DIR`の一部だけを移動しない。鍵を含めて全体を同じ構成で移す。
- `project.json`、`result.json`、鍵ファイルを手編集しない。
- `input/current.xlsx`を直接上書きせず、画面の「Excelを登録」を使う。
- Basic認証の`secrets.enc.json`は案件UUIDと結び付いているため、別案件へコピーしない。
- 同じ`DATA_DIR`を使うアプリを2つ同時に起動しない。単一インスタンス用ロックで拒否されます。
- 画面に案件削除機能はない。完全削除や修復が必要な場合は、バックアップを取ってから開発者の手順に従う。

### 7.5 Security-Cによる保護

新しいrunでは、URL内のユーザー情報や秘密性の高いクエリ値を表示用にマスクし、元URLの同一性確認にはHMAC-SHA-256の識別子を使います。元の秘密付きURLは実行中のメモリで扱い、入力控え、結果、イベントへそのまま保存しない設計です。旧履歴ファイル自体は書き換えず、APIで画面表示するときに安全化します。

AI入力では、URL秘密値に加えてメール、電話、JWT、APIキーらしい値などをマスクします。結果JSONとExcelレポートでは、普通の連絡先情報を業務結果として残す場合があるため、AI入力と同じ範囲でマスクされるとは限りません。

### 7.6 外部へ共有するとき

1. 案件名、ページ本文、URL、クエリ文字列、メール、電話、顧客名を確認する。
2. `[MASKED_...]`があるから安全だと決めつけない。
3. 必要なrun・必要なシートだけを共有する。
4. Excelの「備考」に認証情報を書かない。
5. AI入力JSON、結果JSON、Excelレポートを公開チャネルへ置かない。
6. 共有先の保存・削除ルールを確認する。

### 7.7 ローカル専用アプリとしての注意

- `NITRO_HOST`または起動スクリプトで`127.0.0.1`へ限定する。
- ファイアウォールを開けてLANやインターネットへ公開しない。
- `data/`と`.env`はGitへ追加しない。現在の`.gitignore`では除外されています。
- Windowsの利用者アカウントと`DATA_DIR`のアクセス権を適切に管理する。
- 共用PCで利用しない。必要な場合は専用Windowsアカウントと保存領域を用意する。

## 8. 用語集

| 用語 | 意味 |
|---|---|
| 案件 | 1つのWebサイト検査単位。設定、Excel、履歴をまとめて管理する |
| run | 1回の検査実行。毎回固有のrunIdが付く |
| 期待値 | Excelに入力した、正しいと想定するtitleやdescription |
| 実測値 | 実際のWebページから取得した値 |
| 固有URL | 重複URLをまとめた、実際に検査するページ |
| ページ集約項目 | ページ取得、title、description、Googleタグ、リンク、画像の6項目 |
| 個別詳細 | 各リンク、画像、Googleタグ検出など1件ごとの結果 |
| HTTP状態 | Webサーバーからの応答番号。200番台は成功、404はページなどが見つからないことを表す |
| リダイレクト | あるURLから別URLへ自動転送されること |
| アンカー | URLの`#...`でページ内または別ページの特定位置を示すリンク |
| DOM | ブラウザがページを表示するために組み立てた構造。本ツールはJavaScript描画後の内容も使う |
| Playwright | PC・スマートフォン相当のブラウザ検査に使う仕組み |
| MANUAL | AI入力JSONを人がChatGPT/Codexへ渡し、結果JSONを戻す方式 |
| API | `OPENAI_API_KEY`を使い、アプリからOpenAI APIへ自動で判定を依頼する方式 |
| マスキング | 個人情報や秘密値らしい文字列を`[MASKED_...]`へ置き換えること |
| Security-C | URL秘密情報と外部共有データを保護するための実装上の安全化処理 |
| DATA_DIR | 案件、Excel、履歴、鍵を保存するフォルダー |
| SSRF対策 | アプリを利用してローカル・私設ネットワークへ意図しないアクセスをさせないための制限 |
| CSRF | 別のWebサイトから利用者の意図しない操作を送られる攻撃。本アプリのAPIはトークンなどで防止する |
