## 1. 検査対象と検査項目

### 検査できるWebサイト

Excelに登録した`http://`または`https://`のWebページを検査できます。JavaScriptで表示された後のページを、PCとスマートフォンの両方で確認します。

- PC：1366 × 768
- スマートフォン：375 × 667（Pixel 5相当）
- Basic認証付きサイトに対応
- WordPress「Password Protected」プラグインによるサイト全体のパスワード保護に対応
- 社内・ローカル環境は、案件設定でホストを明示的に許可した場合のみ検査可能

### 主な検査項目

| 項目             | 確認内容                                                       |
| ---------------- | -------------------------------------------------------------- |
| ページ取得       | ページを取得できるか、HTTP状態、最終URL                        |
| title            | Excelの期待値と実際のtitleが完全一致するか                     |
| description      | Excelの期待値と実際のmeta descriptionが完全一致するか          |
| Googleタグ       | 登録したGTM、GA4、Google広告などのID・設置方法                 |
| リンク           | リンク切れ、リダイレクト、アンカー、PDF、`mailto:`、`tel:`など |
| 画像             | PC・スマートフォン別の読み込み、表示、通信エラー、非表示       |
| AIリンク内容照合 | リンク文言とリンク先の内容が意味的に対応するか                 |

### 自動検査とAIリンク内容照合の違い

| 機能              | 役割                                                                             |
| ----------------- | -------------------------------------------------------------------------------- |
| Webサイト自動検査 | titleの完全一致、リンクの応答、画像の読み込みなどを機械的に判定します            |
| AIリンク内容照合  | 「料金を見る」が料金ページへ進むかなど、リンク元とリンク先の意味を補助判定します |

AI判定は補助情報です。AIの結果だけでNGを確定せず、実際のページを人が確認してください。

### 検査できないこと・注意が必要なこと

- デザインの良し悪し、文章の正しさ、法令・アクセシビリティへの適合は自動判定できません。
- h1〜h3は通常検査の独立した判定項目ではありません。AIリンク内容照合の比較材料として使われます。
- ログイン後に複雑な操作が必要なサイト、多要素認証、WordPress Password Protected以外のフォーム認証には対応していません。
- `mailto:`と`tel:`は形式だけを確認し、実際の送信・発信は行いません。
- AI入力やレポートは自動で安全化されますが、機密情報を完全に除去できる保証はありません。外部共有前に内容を確認してください。

## 2. 指定形式のExcelを準備・登録する

### 対応形式

- ファイル形式：`.xlsx`のみ
- ファイルサイズ：20MiB以下
- 必須シート：`納品前のチェック`、`Googleタグ`
- シート名と1行目の見出しは、次の表と完全に同じ文字にします。

### 「納品前のチェック」シート

| 列  | 1行目の見出し | 入力内容                                | 必須     |
| --- | ------------- | --------------------------------------- | -------- |
| A   | ページ名      | 結果画面に表示する分かりやすい名前      | 任意     |
| B   | URL           | `https://example.com/`のような完全なURL | 必須     |
| C   | title         | 正しいと想定するtitle                   | 入力推奨 |
| D   | description   | 正しいと想定するmeta description        | 入力推奨 |

入力例：

| ページ名     | URL                            | title              | description                    |
| ------------ | ------------------------------ | ------------------ | ------------------------------ |
| トップページ | `https://example.com/`         | 会社名｜公式サイト | 会社のサービスをご案内します。 |
| 会社概要     | `https://example.com/company/` | 会社概要｜会社名   | 会社情報をご案内します。       |

titleとdescriptionは、空白や記号、全角・半角を含めて完全一致で判定します。空欄にすると「項目がないことを期待する」のではなく、「期待値が空欄のため要確認」になります。

### 「Googleタグ」シート

| 列  | 1行目の見出し | 入力内容                     | 必須             |
| --- | ------------- | ---------------------------- | ---------------- |
| A   | タグ名        | タグを識別する名前           | 任意             |
| B   | 設置コード    | GoogleタグIDまたは設置コード | 有効な行では必須 |

対応するIDの例は`GTM-...`、`G-...`、`AW-...`、`GT-...`、`DC-...`です。GTMのタグ名やコードに「head用」「body用」がある場合は、設置位置の確認にも使われます。

### 参考にできるExcel

専用テンプレートとして明記されたファイルはありませんが、正しい形式の参考ファイルとして、`web-check-tool`フォルダーの1つ上にある次のファイルを利用できます。

```text
..\web-check-origin.xlsx
```

元ファイルを直接編集せず、必要に応じてコピーを作り、実案件用の値へ置き換えてください。

### Excelを案件へ登録する

1. 案件詳細画面の「入力ファイル」を表示します。
2. 「ファイルを選択」で`.xlsx`を選びます。
3. 「Excelを登録」を押します。
4. 「Excelを案件フォルダへコピー保存しました。原本は変更していません。」と表示されることを確認します。
5. 下に表示される「Excel入力プレビュー」を確認します。

「入力検証OK」なら検査できます。「修正が必要」の場合は、「警告・エラー」の開始不可項目を元Excelで直し、再登録してください。

### よくある入力ミス

| 入力ミス                                   | 対処                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| シート名や見出しが違う                     | 上記の文字へ完全に合わせる。余分な空白にも注意する                     |
| URLが`www.example.com`だけ                 | `https://www.example.com/`のように入力する                             |
| B列が空欄、または`ftp://...`               | 有効なHTTP/HTTPS URLへ直す                                             |
| title・descriptionが数式                   | 数式ではなく文字列の値として貼り付ける                                 |
| A〜D列の入力範囲に結合セルがある           | 結合を解除する                                                         |
| 有効URLが0件                               | URLを1件以上入力する                                                   |
| フィルターで除外したつもりの行が検査される | 行の非表示状態を保存する。フィルター条件だけでは除外されない場合がある |

非表示状態で保存された行は検査対象外になります。重複URLは1つのページとして検査され、期待値に矛盾がある場合は要確認になります。

## 3. ビルド後のアプリを起動する

### 必要な環境

- Windows 11
- Node.js 20以降
- ビルド済みの`.output`フォルダー
- 設定済みの`.env`、またはWindows・PowerShellの環境変数

### 実行するフォルダー

PowerShellを開き、`package.json`、`.env`、`.output`がある`web-check-tool`フォルダーへ移動します。次の`<アプリの保存先>`は、実際にアプリを保存した場所へ置き換えてください。

```powershell
cd "<アプリの保存先>\web-check-tool"
```

### 起動手順

1. PowerShellで、アプリの接続先をこのPCだけに限定します。

   ```powershell
   $env:NITRO_HOST='127.0.0.1'
   ```

2. `.env`を読み込んでビルド済みアプリを起動します。

   ```powershell
   node --env-file=.env .output/server/index.mjs
   ```

   2行を1行ずつ入力しても、まとめて貼り付けても構いません。上から順に実行されます。

   環境変数をWindowsまたはPowerShellへすでに設定済みの場合の基本コマンドは次です。

   ```powershell
   node .output/server/index.mjs
   ```

3. PowerShellを開いたまま、ブラウザで次を開きます。

   ```text
   http://127.0.0.1:3000
   ```

`localhost`やPC名では、APIアクセス制限によりエラーになる場合があります。必ず`127.0.0.1`を使用してください。

### 終了方法

アプリを起動したPowerShellで`Ctrl`+`C`を押します。検査中に終了すると、次回起動時にその検査は「中断」となり、自動では再開しません。

### コードを変更した場合

アプリのソースコードを変更した場合は、起動前に同じフォルダーで再ビルドします。

```powershell
npm run build
```

Excel、案件設定、検査履歴を変更しただけなら再ビルドは不要です。

### 環境変数の注意

- `APP_ENCRYPTION_KEY`：Basic認証情報を保護する32バイトの鍵。既存データと同じ鍵を使用します。
- `DATA_DIR`：案件・Excel・履歴の保存場所。初期値は`./data`です。
- `OPENAI_API_KEY`：AIのAPI方式を使う場合だけ必要です。

通常の`node .output/server/index.mjs`は`.env`を自動で読み込みません。そのため、この手順では`node --env-file=.env ...`を案内しています。

## 4. 案件作成から結果確認までの基本操作

### 1. アプリを起動する

[3. ビルド後のアプリを起動する](#3-ビルド後のアプリを起動する)の手順を行い、`http://127.0.0.1:3000`で「案件一覧」を開きます。

### 2. 案件を新規作成する

1. 「新しい案件」を押します。
2. 「案件名」を入力します。
3. まずは「ページ並列数」2または3、「タイムアウト（ミリ秒）」30000を目安にします。
4. 公開サイトなら認証方式を「なし」にします。
5. 「案件を作成」を押します。

### 3. 指定形式のExcelを登録する

案件詳細の「入力ファイル」で`.xlsx`を選び、「Excelを登録」を押します。「Excel入力プレビュー」が「入力検証OK」になることを確認します。

### 4. 必要な検査設定を行う

案件詳細の「基本設定」で、必要に応じて次を変更し、「変更を保存」を押します。

- ページ並列数：1〜3
- タイムアウト：1,000〜120,000ミリ秒
- ローカル・私設IPへの明示許可ホスト
- AIリンク内容判定：OFF、MANUAL、API
- 認証方式：なし、Basic認証、パスワード保護

通常の自動検査だけを行う場合、AIは「OFF」で構いません。

### 5. 検査を開始する

「Webサイト自動検査」の「検査開始」を押します。Excelが未登録、案件がアーカイブ中、または別の検査が実行中の場合は開始できません。

### 6. 検査の進捗を確認する

画面には、現在の状態、「完了ページ数 / 総ページ数」、パーセントが表示され、検査中は2秒ごとに更新されます。

状態は「開始待ち」→「Excel読込中」→必要に応じて「認証中」→「検査中」→「完了」と進みます。API方式では「AI判定中」も表示されます。

### 7. 検査結果を確認する

「ページ別結果」を開き、特にNG、要確認、未確認を確認します。

| 判定   | 意味                                           |
| ------ | ---------------------------------------------- |
| NG     | 明確な不一致、欠落、リンク切れ、取得失敗など   |
| 要確認 | 人の確認が必要。期待値空欄や例外的な応答など   |
| 未確認 | ページを取得できず、その項目を検査できなかった |
| 対象外 | レスポンシブ非表示などで検査対象から外した     |
| OK     | 実装された検査基準を満たした                   |

各ページで、期待値、実際の値、メッセージ、根拠を確認できます。「リンク検査詳細」「画像検査詳細」「Googleタグ検出詳細」も必要に応じて開きます。

### 8. Excelレポートを出力する

検査が終了したら、対象の履歴を選び、「Excelレポートをダウンロード」を押します。

レポートには「検査サマリー」「NG・要確認一覧」「全検査結果」の3シートがあります。「修正状況」と「備考」は出力したExcelだけの情報で、再出力すると初期状態へ戻ります。

## 5. 各機能の簡単な使い方

| 機能               | 基本操作・見方                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------- |
| 案件の編集         | 「案件一覧」で「編集」→基本設定を変更→「変更を保存」                                     |
| アーカイブ         | 「アーカイブ」で通常一覧から外す。データは削除されない。上部の「アーカイブ」から解除可能 |
| Basic認証          | 認証方式で「Basic認証」→ユーザー名・パスワードを入力。保存済みなら変更時だけ再入力       |
| Password Protected | 認証方式で「パスワード保護」→パスワードを入力。WordPressの対応プラグイン用               |
| PC・モバイル検査   | 検査開始時に自動実行。画像詳細では端末ごとの結果を確認できる                             |
| リンクチェック     | 「リンク検査詳細」でhref、HTTP状態、リダイレクト、最終URLを確認                          |
| 画像チェック       | 「画像検査詳細」で端末、画像URL、出現箇所、通信・表示結果を確認                          |
| 検査履歴           | 左側の「検査履歴」で日時を選ぶと、そのrunの保存済み結果を表示                            |
| 再検査             | 終了済み履歴で「全URLを再実行」→検査条件とAIモードを選択→「新しいrunで再実行」           |
| 履歴比較           | 「履歴を比較」で変更前を「比較元run」、変更後を「比較先run」にして「比較する」           |
| Excel出力          | 終了済み履歴で「Excelレポートをダウンロード」                                            |
| JSON出力           | 「JSON結果をダウンロード」。実行中はその時点までの途中結果を出力                         |

### AIリンク内容照合（手動JSON方式）

1. 案件の「AIリンク内容判定」を「MANUAL」にし、「変更を保存」します。
2. 新しい検査を実行します。
3. 「AI判定用JSONをダウンロード」を押し、機密情報が残っていないか確認します。
4. 「Codex用の指示文をコピー」を押します。
5. ChatGPTまたはCodexへ指示文を貼り、ダウンロードしたJSONを添付します。
6. 作成された判定結果JSONを保存します。
7. 「AI判定結果JSONを取り込む」でファイルを選びます。
8. 「AI判定詳細」で理由を確認します。

AI結果は、`match`がOK、`possible_mismatch`が要確認、`undetermined`が判定不可です。AIだけで最終判断しないでください。

## 6. 困ったときの確認事項

| 症状                                       | 確認すること                                                          |
| ------------------------------------------ | --------------------------------------------------------------------- |
| 画面を開けない                             | PowerShellでアプリが起動中か、URLが`http://127.0.0.1:3000`か確認      |
| 「このAPIは127.0.0.1からのみ利用できます」 | `localhost`ではなく`127.0.0.1`で開き直す                              |
| 「検査開始」を押せない                     | Excel登録、アーカイブ状態、実行中の別検査を確認                       |
| Excelが「修正が必要」                      | 入力プレビューの「開始不可」を直して再登録                            |
| 認証に失敗する                             | 認証方式、ユーザー名、パスワードを再確認して保存                      |
| ページ取得や画像が失敗する                 | 対象URLを通常のブラウザで確認し、必要ならタイムアウトを増やして再検査 |
| AI結果JSONを取り込めない                   | 元のAI入力と指示文を使い、説明文を含まないJSONファイルとして再作成    |

より詳しい判定基準、エラー、データ保存・バックアップについては、[操作マニュアル](操作マニュアル.md)を参照してください。
